# supabase/

Database migrations (including server-side free-catch enforcement), Edge Functions
(notifications, purchases, account deletion), and seed data. Schema is defined in [../docs/TSD.md §3](../docs/TSD.md). Migrations are timestamped and
applied by the Database migrate workflow (below).

## Applying migrations

Migrations in `migrations/` are timestamped and applied **in order** by the **Database migrate**
workflow (`.github/workflows/db-migrate.yml`, `db/migrate.py`): dispatch it with `mode: apply`.
It records each applied file, so a re-run applies only new ones. `mode: verify` runs
`pipeline/db/verify.py`, which checks the live project against what the migrations promise (RLS,
grants, functions, limits). Every migration is also exercised in CI: the schema tests read the
SQL, and the `needs_pg` tests apply it to a real Postgres (`pipeline/tests/pg_harness.py`).

The full list is the directory itself; there is no hand-maintained copy here to drift.

## Edge Functions

| Function | Auth | Called by |
|---|---|---|
| `delete-account` | user JWT (`verify_jwt` on) | the app, Settings → Delete account (T-093) |
| `send-notifications` | `x-cron-secret` header (`verify_jwt` **off**) | pg_cron job `send-notifications`, hourly at :07 (T-201) |
| `revenuecat-webhook` | `Authorization` header with the webhook secret (`verify_jwt` **off**) | RevenueCat, on every purchase, refund and transfer (T-217, T-267) |

The functions import app logic from `functions/_shared/lib`, a **generated** JS copy of the
TypeScript in `lib/` (Deno needs `.js` import specifiers): the notification engine, FCM auth,
species media and the RevenueCat event planner. After changing any of `lib/pushDispatch.ts`,
`lib/fcmAuth.ts`, `lib/species/media.ts`, `lib/revenuecatEvents.ts` or anything they import, run
`node scripts/edgeShared.js` and commit the result — `__tests__/edgeShared.test.js` fails while
the copy is stale. Pushing to `main` redeploys the functions (`deploy-functions.yml`, T-206).

Edge Function secrets (set by the Director in the Supabase dashboard, never in the repo):
`FCM_SERVICE_ACCOUNT` (the Firebase service-account JSON), `REVENUECAT_WEBHOOK_SECRET`,
`REVENUECAT_SECRET_KEY` (deletes a customer with no purchases on account deletion, T-280) and
`REVENUECAT_ACCEPT_SANDBOX` (`false` at launch, T-282). The cron secret is generated by the migration into Vault (`push_cron_secret`) and never leaves the
database.

Manual runs, from the SQL editor (the response lands in `net._http_response`):
```sql
select net.http_post(
  url := 'https://subjdoiicfmiimtvlzsg.supabase.co/functions/v1/send-notifications',
  headers := jsonb_build_object('Content-Type','application/json',
    'x-cron-secret', (select decrypted_secret from vault.decrypted_secrets where name = 'push_cron_secret')),
  body := '{"dryRun": true}'::jsonb);   -- or {"testUserId": "<uuid>"} to send to one user now
```
